# Skill: Documentation Synchronization

## Главный принцип

Репозиторий является долговременной памятью инфраструктурной команды. История чата не является источником истины.

Разделяй информацию:

```text
tasks/  = что сейчас делаем
docs/   = как фактически устроена система
skills/ = как повторяемо выполнять работу
Git     = история изменений
```

## В начале сессии

Прочитай:

- `AGENTS.md`;
- `docs/agent/START_PROMPT.md`;
- `tasks/CURRENT.md`;
- `docs/state/latest-audit.md`;
- только релевантные skills.

## Во время задачи

После значимого этапа обновляй `tasks/CURRENT.md`:

- выполненные пункты;
- блокеры;
- важные решения;
- следующий шаг.

Не делай отдельный commit ради одной галочки, если task state относится к тому же техническому изменению.

## Когда обновлять docs

Если изменилось фактическое устройство инфраструктуры, обнови соответствующий документ:

- architecture;
- state;
- runbook;
- monitoring;
- app README.

Документация должна отвечать как минимум:

```text
что изменилось
зачем
где находится
как проверить
как откатить
```

## Когда обновлять skill

Если во время выполнения найдено универсальное повторяемое решение или хороший алгоритм диагностики — обнови `skills/*/SKILL.md`.

Не оставляй reusable knowledge только внутри `tasks/CURRENT.md`.

## Завершение задачи

Когда Definition of Done выполнен:

1. обнови `tasks/CURRENT.md`;
2. синхронизируй docs и skills;
3. перенеси финальный документ задачи в `tasks/archive/YYYY-MM-DD-short-name.md`;
4. создай следующую CURRENT-задачу или переведи `tasks/CURRENT.md` в `Status: IDLE`;
5. сделай тематический commit;
6. выполни push.

Никогда не удаляй историю задач.

## Критерий качества

Свежий агент должен после `git pull` суметь прочитать репозиторий и продолжить работу без пересказа предыдущего чата пользователем.
